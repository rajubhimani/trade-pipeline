# [done] Pin dependencies with compatible-release specifiers (deps) — id: T-26

Added: 2026-07-27
Completed: 2026-07-27
Notes: Every dependency in pyproject.toml used a bare `>=` floor with no ceiling — `uv lock --upgrade` could silently jump onto the next major release and break on a removed/renamed/deprecated API with no warning (already happened in practice: `redis>=5.2` had drifted to 8.0.1). Switched every base + dev/dagster/temporal dependency to PEP 440 `~=` (compatible release): `X.0` level for packages already at major >=1 (allows minor+patch, blocks next major), `0.Y.0` level for pre-1.0 packages (`fastapi`, `uvicorn`, `asyncpg`, `prometheus-client`, `zstandard`) since a 0.x minor bump is their de facto breaking boundary. Floors raised to match what uv.lock had already resolved to, not left at the original stale floor. Verified: `uv lock` after the change resolved the same 132 packages at the same versions (no-op), `uv sync --locked` succeeds for both the base and full dependency groups, ruff clean, pip-audit clean, full test suite (116 tests) passes against real Postgres/Redis. See `docs/DECISIONS.md` "Compatible-release (~=) version pins, not bare >=" for full rationale.
