# [done] Add opt-in Redpanda broker swap alongside default Kafka (deploy) — id: T-27

Added: 2026-07-27
Completed: 2026-07-27
Notes: Default stack stays on Kafka (this project's point is demonstrating real Kafka internals for interview prep), but added Redpanda as an opt-in swap for the ops-simplicity/no-JVM tradeoff discussion. Implemented `docker-compose.redpanda.yml` — an override file (not Compose `profiles:`, which can't swap what a service *named* kafka points at without duplicating every dependent service) that redefines the `kafka` service under the same name/hostname/ports with `redpandadata/redpanda:v26.1.14` + an `rpk cluster health` healthcheck. `make up-redpanda` runs both compose files together; default `make up` untouched. Also fixed a real bug found while testing this: `common/migrations.py`'s `upgrade_to_head` used a hardcoded `Path(__file__).resolve().parents[3]` to find `alembic.ini`, which only worked for local/editable installs — the Dockerfile's `uv sync --no-editable` installs the package one level deeper (site-packages), so it silently pointed at the wrong directory and `migrate`/consumer startup failed with a confusing "No 'script_location' key found" instead of a clear error. Fixed by searching parent directories for `alembic.ini` instead of assuming a fixed offset. Verified against real containers (not just `docker compose config`): full producer→broker→consumer→Postgres flow confirmed on both Redpanda and Kafka from a clean volume, `make demo` passes on both, full test suite (116 tests) passes. See `docs/DECISIONS.md` for full rationale.
